# Diabetes Clinical Decision Support Platform

پلتفرم دوزبانهٔ فارسی و انگلیسی برای پشتیبانی تصمیم‌گیری بالینی پزشکان در مدیریت دیابت.

> **وضعیت پروژه:** این مخزن در مرحلهٔ طراحی اولیه است. اسناد فعلی مرزهای محصول و معماری پیشنهادی را تعریف می‌کنند و جایگزین قضاوت بالینی پزشک نیستند.

## چشم‌انداز / Vision

این سامانه قرار است راهنماهای معتبر ADA و EASD را به پیشنهادهای قابل‌ردیابی و نسخه‌بندی‌شده تبدیل کند؛ بدون آن‌که نقش پزشک را در تصمیم نهایی جایگزین کند. رابط کاربری و محتوای بالینی به فارسی و انگلیسی ارائه می‌شوند و فهرست داروها می‌تواند نام‌های ژنریک و برندهای موجود در بازار ایران را با اولویت قابل‌تنظیم نمایش دهد.

The platform turns authoritative ADA and EASD guidance into traceable, versioned recommendations while keeping the clinician responsible for the final decision. Clinical content and user interfaces are available in Persian and English, with configurable generic/brand medication display for the Iranian market.

## قابلیت‌های هدف / Planned capabilities

- ثبت داده‌های ضروری بیمار و تولید پیشنهاد همراه با دلیل، منبع و نسخهٔ قانون؛
- نسخه‌بندی مستقل مجموعه‌قوانین بالینی و انتشار کنترل‌شدهٔ آن‌ها؛
- به‌روزرسانی سالانه و به‌روزرسانی اضطراری راهنماهای ADA و EASD؛
- مدیریت داروهای ژنریک، شکل و دوز دارویی، برند ایرانی، تولیدکننده و وضعیت بازار؛
- انتخاب اولویت نمایش `generic-first` یا `brand-first` در سطح سازمان و کاربر؛
- پنل مدیریت دوزبانه برای کاربران غیر برنامه‌نویس با گردش‌کار پیش‌نویس، بازبینی، تأیید و انتشار؛
- داشبورد مدیریتی برای مشاهدهٔ تعداد کاربران و میزان استفاده از سامانه با رعایت حریم خصوصی؛
- ثبت رویدادهای ممیزی و امکان بازسازی خروجی تاریخی سامانه.

## اصول ایمنی

1. هر پیشنهاد باید نسخهٔ قانون، نسخهٔ راهنما، زمان ارزیابی و داده‌های ورودی مؤثر را ثبت کند.
2. محتوای پیش‌نویس یا منقضی هرگز در موتور فعال اجرا نمی‌شود.
3. تغییر بالینی با تأیید حداقل یک بازبین بالینی مجاز منتشر می‌شود؛ نویسنده نباید تنها تأییدکننده باشد.
4. در نبود دادهٔ کافی، سامانه به‌جای حدس‌زدن، محدودیت و نیاز به بررسی پزشک را اعلام می‌کند.
5. توصیه‌ها توضیح‌پذیرند و پیوند دقیق به منبع دارند؛ سامانه ابزار پشتیبان است، نه ابزار تشخیص یا تجویز خودکار.

## ساختار مخزن

```text
apps/
  web/                 # رابط پزشک و پنل مدیریت Next.js
  api/                 # API ماژولار NestJS/Fastify
packages/
  clinical-engine/     # موتور قطعی و مستقل از نمایش دارو
  contracts/           # قراردادهای type-safe بین وب، API و موتور
infra/
  postgres/            # migration و جداسازی چندسازمانی
docs/                  # تصمیم‌های معماری، محصول و حاکمیت
```

این پروژه یک monorepo TypeScript با `pnpm` و Turborepo است. برای اجرا پس از نصب وابستگی‌ها:

```bash
pnpm install
pnpm build
pnpm test
pnpm dev
```

رابط وب در `http://localhost:3000` و API در `http://localhost:3001` اجرا می‌شوند. migration آغازین PostgreSQL در `infra/postgres/001_initial.sql` است.

مسیر اولیهٔ Type 2 در `http://localhost:3000/type-2` و پنل مدیریت در `http://localhost:3000/admin` قرار دارد. هیچ پروتکل درمانی تا زمان بازبینی و تأیید پزشک خروجی بالینی تولید نمی‌کند. جزئیات در [پایهٔ پروتکل Type 2](docs/TYPE_2_PROTOCOL_FOUNDATION.md) آمده است.

در وضعیت فعلی، همهٔ مسیرهای بالینی وب بدون gate تأیید پزشک یا Admin قابل استفاده‌اند. پنل مدیریت فقط با نشانی مستقیم `/admin` باز می‌شود و در ناوبری عمومی نمایش داده نمی‌شود.

رابط وب به‌صورت PWA قابل نصب است و manifest، service worker و آیکن‌های نصب را در خود دارد. در مرورگرهای پشتیبان، دکمهٔ «نصب برنامه» در نوار بالای برنامه نمایش داده می‌شود.

مسیر Type 2 علاوه بر HbA1c فعلی، HbA1c هدف فردی را دریافت می‌کند و فاصله از هدف را در اولویت‌بندی مسیر درمان لحاظ می‌کند. طبق ADA 2026، HbA1c بالاتر از ۱۰٪ یا علائم واضح هایپرگلیسمی/کاتابولیسم مسیر بررسی انسولین را برجسته می‌کند؛ در نبود هایپرگلیسمی شدید، فاصلهٔ حداقل ۱٫۵٪ از هدف مسیر درمان ترکیبی با اولویت GLP-1 RA یا dual GIP/GLP-1 RA را نمایش می‌دهد. این خروجی دوز یا نسخه تولید نمی‌کند.

## تصمیم‌های V1

- فقط دادهٔ ناشناس؛ ذخیرهٔ اطلاعات قابل‌شناسایی بیمار خارج از محدوده است.
- چندسازمانی از ابتدا، با RLS در PostgreSQL.
- انتخاب مسیر نوع ۱، نوع ۲ و بارداری در رابط وجود دارد؛ فقط مسیر نوع ۲ پس از تأیید محتوای بالینی قابل فعال‌شدن است.
- نمایش نام ژنریک پیش‌فرض است. برندهای ایران فقط با منبع، بازبینی و اولویت ادمین قابل نمایش می‌شوند.
- کاتالوگ جهانیِ مرجعِ واردشده فقط در پنل Admin و با وضعیت «نیازمند اعتبارسنجی ایران» دیده می‌شود؛ جزئیات در [ورود کاتالوگ مرجع](docs/REFERENCE_CATALOGUE_IMPORT.md) است.

جزئیات در [محدودهٔ V1](docs/PRODUCT_SCOPE.md) و [کاتالوگ دارویی ایران](docs/IRAN_MEDICATION_CATALOG.md) آمده‌اند.
